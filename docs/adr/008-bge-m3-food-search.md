# Context

USDA Foundation Foods descriptions are primarily English, while Victus users can search in Spanish and other languages. Substring search is predictable for exact names but cannot reliably identify cross-language equivalents or colloquial food names.

# Decision

Keep PostgreSQL as the food-search datastore and add pgvector documents with 1024-dimensional BGE-M3 embeddings. `GET /api/foods/search` combines an exact/alias lexical ranking with vector cosine ranking through reciprocal-rank fusion. If BGE-M3 is unavailable, it returns the lexical ranking with `mode: lexical-fallback`.

The BGE-M3 endpoint URL and token are environment-only configuration. Documents are regenerated by an idempotent backfill job when their SHA-256 content hash changes. Canonical USDA data remains the source of truth; vectors and aliases are derived search data.

# Consequences

- The existing `GET /api/foods` contract remains unchanged.
- Deployments need PostgreSQL with the pgvector extension installed.
- A failed semantic provider does not make food search unavailable.
- Locale-aware aliases can improve culturally specific matching without translating the whole USDA catalog.

# Alternatives considered

- A dedicated vector database was rejected because the catalog is small and already belongs in PostgreSQL.
- Semantic-only retrieval was rejected because exact food names and aliases need deterministic lexical recall.
- A paid embedding provider was rejected for the initial implementation because a BGE-M3 endpoint already exists in the operating environment.
